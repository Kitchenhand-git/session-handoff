# 会话交接单

把「跨会话续作」这件事变成自动的：每轮结束留一份最新的交接单，新开对话时先问你要不要接着上一份干。

## 解决什么问题

DSH 的会话不共享上下文：换一个会话，上一会话做过什么、产出在哪、哪些方案已经否掉，全都没有。手动写交接单要靠人记着写、靠人复制路径。本插件把两头都自动化。

## 每轮结束自动刷新

一轮对话结束后，插件把「上一版交接单 + 本轮摘要」合成一份新的交接单，写入项目目录：

```
D:\DSH\项目\<项目名>\交接\<YYYYMMDD-HHMM>-<会话id前8位>-交接单.md
```

- 同一会话固定一个文件，每轮**覆盖**刷新，不会几十轮堆出几十个文件。
- 正文沿用工作区交接模板的 9 节结构（状态、目标、产出物与绝对路径、关键决定、没做完的、坑、用户偏好、待确认、开工三步）。
- 第 3 节的产出物列表来自本轮真实工具调用参数，并标注文件当前是否存在。
- 默认用会话模型润色；也可以配置成不调用模型的确定性稿。

## 新开对话先问一句

新会话的第一个 step，插件会把「上一份交接单的绝对路径、项目、最后更新时间」注入模型上下文，并要求它先问一个问题：

- **A 续作**：切到交接单记录的工作目录，读完交接单，按第 9 节开工（第 4 节已否掉的方案不重提，第 8 节待确认一次问清）。
- **B 新任务**：完全忽略这份交接单。

没有候选交接单（或超过 `maxAgeDays`）时不做任何注入，新会话零打扰。

## 手动入口

`/handoff` 立即刷新；`/handoff status` 看开关与落盘位置；`/handoff list` 列最近几份；`/handoff read <路径>` 查看内容；`/handoff off` 只对本会话停用自动刷新；`/handoff models` 看可用模型路由。

模型另有 `handoff` 工具，用户说「出交接单」「交接一下」时可直接刷新。

## 配置要点

- `summaryMode: deterministic`：完全不调用模型，运行成本归零。
- `turnEndEnabled: false`：只保留手动生成。
- `maxDigestChars` / `maxPrevChars`：直接决定每次生成的输入规模。
- `newSessionAsk: false`：不再在新会话里询问。

## 限制

1. 「询问续作」是由模型按注入提示调用 `ask_user_question` 完成的，模型没有遵守时不会强制弹问。
2. 交接单是自动稿，除第 3 节的文件存在性外不做人工复核；金额、日期等结论性内容仍需人工确认。
3. 滚动覆盖只保留最新状态，不保留历史版本。
4. 卸载本插件不会删除已生成的交接单；旧会话里的注入消息仍可正常重开。
